# Desktop Local And Official Icons

T3 Code can install a local desktop build beside the official app by giving the local build its own Windows identity, state directory, launcher, and shortcut.

## Official App

The official app keeps the normal production identity:

```text
com.t3tools.t3code
```

It also uses the normal production state directory:

```text
C:\Users\<user>\.t3
```

## Local App Identity

The local install identity is defined in:

- `scripts/install-desktop-build.ts`

```ts
const LOCAL_DISPLAY_NAME = "T3 alpha.local";
const LOCAL_WINDOWS_APP_USER_MODEL_ID = "com.t3tools.t3code.alpha.local";
```

This separate `AppUserModelID` is what lets Windows treat the local build as a separate taskbar app from the official build.

## Local Launcher

The local Windows launcher is generated by:

```ts
renderWindowsLocalLauncher(...)
```

It writes a `.cmd` file that sets local-only environment variables before starting the packaged executable:

```bat
set "T3CODE_HOME=<local-state-dir>"
set "APPDATA=%T3CODE_HOME%\appdata"
set "T3CODE_DESKTOP_DISPLAY_NAME=T3 alpha.local"
set "T3CODE_DESKTOP_APP_USER_MODEL_ID=com.t3tools.t3code.alpha.local"
set "T3CODE_DISABLE_AUTO_UPDATE=true"
start "" "%~dp0<exe-name>" %*
```

These values keep the local app isolated from the official app:

- `T3CODE_HOME` points at the local state directory.
- `APPDATA` points at local Electron profile data.
- `T3CODE_DESKTOP_DISPLAY_NAME` changes the app display name.
- `T3CODE_DESKTOP_APP_USER_MODEL_ID` changes the Windows taskbar identity.
- `T3CODE_DISABLE_AUTO_UPDATE` prevents local builds from updating as if they were official builds.

## Shortcut

The Windows shortcut is generated by:

```ts
renderWindowsShortcutScript(...)
```

The shortcut target points at the generated local launcher:

```powershell
$shortcut.TargetPath = "<install-dir>\T3 alpha.local.cmd"
```

The shortcut icon points at the local executable:

```powershell
$shortcut.IconLocation = "<install-dir>\<local exe>,0"
```

The shortcut also embeds the local `AppUserModelID` as the `System.AppUserModel.ID` property (`PKEY_AppUserModel_ID`). WScript.Shell cannot write shortcut properties, so the generated script stamps it through the ShellLink COM object's `IPropertyStore` after saving the basic fields. Without this property, Windows cannot match the pinned shortcut to running local windows: clicking the pin may not focus the app, and the running app shows up as a second, separate taskbar icon.

That means clicking the local icon launches the local environment, while the official icon still launches the official app.

## Direct Taskbar Pins

Windows can sometimes pin the executable directly instead of the generated launcher. To keep those direct pins isolated, the local installer writes metadata beside the executable:

```text
.t3code-install.json
```

The bootstrap code lives in:

- `apps/desktop/src/app/DesktopInstallBootstrap.ts`

At startup it reads `.t3code-install.json` and applies:

```text
T3CODE_HOME
APPDATA
T3CODE_DESKTOP_DISPLAY_NAME
T3CODE_DESKTOP_APP_USER_MODEL_ID
T3CODE_DISABLE_AUTO_UPDATE
```

This keeps direct taskbar launches on the same local identity and local state directory even when the `.cmd` launcher is bypassed.

## Result

Windows sees the official and local builds as different apps:

```text
Official: com.t3tools.t3code
Local:    com.t3tools.t3code.alpha.local
```

Because they also use different state directories, the two icons can coexist without sharing sessions, Electron profile data, or update behavior.
