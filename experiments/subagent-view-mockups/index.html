Subagent views — twelve mockups

A parent thread can fan out work two ways. Thread tasks are real threads — own session, own model, steerable, durable. Provider-native subagents (e.g. Claude Code's Task tool) run inside the parent's session — they cannot be steered or cancelled, have no model of their own, and today surface only as a workflow card buried in the transcript. These mockups explore three ways to close that gap, four variants each. Sibling mockup: ../thread-tasks-mockups/.

Option 1 — Sidebar parity

open option →

Native subagents appear as rows inside the parent's sidebar task group, next to real task threads. Hovering a row peeks it: a task row shows the standard mini thread window (steer, cancel, open thread); a native row shows option 2's honest window with the disabled composer. Clicking acts — a task row opens its thread, a native row jumps to its run in the transcript. Add &peek=t1|t2|w1..w4 to open a row's peek directly.

1ASplit section rec Two labelled sub-sections — "Tasks" and "In-session agents" — so the capability difference is structural, not iconographic. Costs vertical space; the two kinds can never interleave by recency. 1BMerged, icon-coded One flat start-time-ordered list; kind shown only by a leading icon plus tooltip, with a "view only" tag on hover. Densest and smallest change — but the tooltip does all the honesty work. 1CTurn-grouped Natives nested under a collapsible "Turn 4 · 4 workers" header mirroring the workflow card 1:1. Teaches when agents ran; scales poorly across many turns. 1DMetrics-forward Merged running-first list with tokens · tools · duration at rest on every row. Best for "what is this costing me"; noisiest, and usage data isn't guaranteed.

Option 2 — Mini-window parity

open option →

The existing task peek window also opens on a native subagent, launched from the transcript's workflow card. Steering is impossible, so the composer is disabled with a stated reason — or removed entirely. Add &w=w1..w4 to pick the worker (w2 running, w3 failed).

2ASame anatomy, honest composer rec Pixel-faithful to the task mini window; the composer is present but disabled with the reason spelled out, and "Open thread ↗" becomes "Show in transcript". One window to learn for both kinds. 2BReceipt card No composer at all — a read-only "agent receipt": stat cells, result block, copy button, full-output file path. Honesty by subtraction; dead-ends the user on failures. 2CPeek → promote Adds a primary "Promote to task thread" action that re-runs the prompt as a real, steerable task. The only variant that adds a capability — and sells a bridge that doesn't exist yet. 2DLive ticker A monitor for running workers: ticking elapsed readout, timestamped progress beats, pulsing last-tool chip. Great for watching; the data model can't feed the beat log today.

Option 3 — Mirror threads

open option →

Each native subagent is mirrored into a read-only thread: a real sidebar row, normal navigation, a thread view of whatever the provider actually streamed — permanently read-only. The tension: the mirror promises "thread" but can't deliver thread capabilities, and the transcript may be partial.

3ALocked chrome Full task-thread chrome with the composer replaced by a lock banner. Lowest learning curve — and the most credible-looking, which makes it the most dishonest about partial data. 3BGhost rows Sidebar mirrors dimmed and italicised, thread view drops the composer zone entirely. Calm and cheap; honesty carried entirely by styling is honesty carried weakly. 3CProvenance & gaps rec Every beat tagged with its source, every unstreamed span drawn as an explicit gap row. The only variant where a partial replay can never pass as a complete transcript; noisiest, and needs per-beat stream data that doesn't exist yet. 3DCompletion archive Mirrors created only when a subagent finishes or fails — running natives stay in the turn card. No fake live threads; the sidebar stops being the one place to see all parallel work.
Everything here is static HTML over file:// — no server, no build. Deep links: ?v=1..4 picks a variant inside an option (option 1 also takes &peek=t1|t2|w1..w4 to open a row's peek; option 2 also takes &w=w1..w4). Per-variant trade-offs and the data-gap analysis are in README.md and each option's NOTES.md.
