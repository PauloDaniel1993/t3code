# T9 — browser verification pass (OpenSpec 6.1–6.8)

## Overall verdict

**FAIL — one shared narrow-viewport rendering defect remains.** All lifecycle states, deep
links, theme-preservation paths, effective-contrast checks, `file://` resources, frozen-v1
checks, and reference-alignment disclaimers passed. At a 320 px viewport, however, every page
that contains a fixed 390 px `.phone` permanently clips the left 29 px of the phone's screen;
the page can scroll only to the right, so the missing strip cannot be reached.

The T3 Code preview was tried first. It could open an automation-capable `about:blank` tab, but
both direct `file://` navigation and an in-page `location.href` assignment were rejected or
left the tab at `about:blank`. Per the unattended fallback instruction, all render verification
below was therefore performed in local headless Chrome 150 over the original `file://` URLs,
using the browser debugging protocol for computed styles, geometry, navigation, console, and
network evidence. No server, build, or network source was used.

  390 px, the screen itself is fully visible.
