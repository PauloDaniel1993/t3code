## Page-local CSS rules (all reported gaps — mockup.css untouched)

Four rules in the page's `<style>` block, each commented in situ:

1. `.trow.selected { background: var(--selected) }` — v1 marked the sheet-owning backdrop row
   with `.trow.selected`; v2's shared sheet has no such class (only the token). Needed so the
   row under the sheet stays visibly selected.
2. `.sh-agents-head b { color: var(--fg); font-weight: 550 }` — the shared sheet styles
   `.wcard-head b` but not `.sh-agents-head b`; v1 hardcoded `color:#d5d7de` inline, which is
   both illegal in v2 and dark-only. Token equivalent.
3. `.sh-top { flex-wrap: wrap; row-gap: 6px }` + `.sh-top .sh-btn { flex: none }` — the shared
   `.sh-top` is nowrap; at 320px the agent sheet's header (`Failed · tool-use budget exceeded`
   - "Show in transcript" + close ≈ 360px of content) would clip. Wrapping drops the buttons
     to a second line; the full reason sentence stays readable. The one honesty-driven layout
     compromise: at 320px the agent sheet's header is two lines tall.
4. `.sh-composer.disabled { opacity: 1 }` — overrides the shared `opacity: 0.65`. That opacity
   drops the §7.2-mandated reason sentence to **≈2.6:1 in both themes** (computed: `--dim` at
   0.65 over the sheet composites — CONTRAST.md measures full-strength `--dim` at 4.69:1 dark /
   4.93:1 light). The disabled read still comes from the greyed `.sh-send` (`--border2` bg) and
   the `--dim` note. Recommend the shared sheet drop the opacity; until then this page keeps
   the explanation legible.

`.sheet`'s own background is never touched — `--sheet-bg` translucency and the
`backdrop-filter: blur(18px)` have show-through as designed.

## Judgement calls

- **`?task=<id>` over `?view=`** for flow-3 links — brief over CONVENTIONS, flagged above.
- **Dismissal navigates.** Dim/grabber/✕/Escape go back to flow-1 with `?peek=` set so the
  user returns to the list with the owning row still highlighted; `a4` returns to `peek=task`.
  Flow-1's `?peek=` values are its declared contract, so this is safe against the sibling's
  work.
- **"Show in transcript" target.** Linked to the owning task's flow-3 thread view. Flow-3 has
  no declared agent anchor; if the sibling adds one (e.g. `?task=task#a4` or `?agent=a4`), this
  link should gain the fragment/param.
- **Failed rows in the sheet's agents block show the reason instead of the duration** (v1
  showed only `9s` etc. next to a red ⊗). Hard rule 1 outranks v1 fidelity; the full usage
  triple for a4 still appears in its own sheet's danger chip, and OK rows keep their durations.
- **Agent rows remain inert** (CONVENTIONS §5: view-only, may offer only "Show in transcript").
  The agent sheet is reachable via `?sheet=a4`, exactly as in v1.
- **Enabled composer and Cancel toast instead of acting** (`Steer this task… (mock)`,
  `Cancel task (mock)`), matching chrome.html's furniture pattern; the disabled composer is
  inert — its note is the explanation.
- **Composer stays inside `.sheet-scroll`** (v1 placement — scrolls with content) rather than
  pinned below the scroll region.
- **Added `title` attributes** to `.dchip` and `.ret` per the CONVENTIONS §5 examples (v1
  lacked them); backdrop rows carry the same `data-unit` ids as v1 so flow-1's `?peek=` and my
  `?sheet=` agree.
