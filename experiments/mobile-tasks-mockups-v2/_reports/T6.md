## Missing / wrong / ambiguous in CONVENTIONS.md

Reported per §1/§8 — gaps the shared sheet should probably own, plus ambiguities I resolved:

1. **No cancelled counter class.** `.cnt-ok`/`.cnt-fail` exist; `.cnt-cancel` does not. My
   page-local stopgap above. If flow-1 or flow-2 render cancelled rollups they will need the
   same thing — promote it rather than letting four copies drift.
2. **No `.sh-evt.cancelled`.** `.sh-evt.failed` exists; the amber lifecycle row does not.
3. **No `.wrow.cancelled` name-dim.** `.wrow.failed .wname` dims; cancelled rows need the same.
4. **No unread indication anywhere.** §7.6 requires “an unread marker on the parent” but no
   class or form is specified; `.tbadge` is the per-thread “#10” form and its number can't be
   invented for another thread. Stopgap: `.udot` + `.unread`. The convention should pin one
   form before flow-1 invents another.
5. **`.picked` deep-link highlight is sub-row-scoped.** Fine for flow pages; a whole-device
   target needed a page-local form. Worth one line in §3 if any future page deep-links at
   device granularity.
6. **`.sh-agents-head <b>` is unstyled.** v1 option 2 hardcoded `color:#d5d7de` on it — which
   itself violates the v2 no-hardcoded-color rule. I used a plain `<b>` (inherits `--muted`).
   The shared sheet should add `.sh-agents-head b { color: var(--fg); font-weight: 550 }`
   exactly as `.wcard-head b` already does.
7. **Ambiguity: queued and zero-fail scenarios are unpinned.** §7.6 names the single,
   all-failed, cancelled, and unread mappings but not queued or zero-fail. I chose: queued =
   the mockups task pre-start (list); zero-fail = the mockups task's turn with all ten ✓
   (maximal contrast against v1's only rendering). No rule fought this.
8. **Ambiguity: is a cancelled task steerable?** Unspecified. I disabled the composer with the
   reason in words (conservative reading; the rule-2 pattern is then exercised on a task, not
   only on an agent). If the product answer is “steering a cancelled task restarts it”, the
   sheet needs a different treatment — flag for review.
9. **Ambiguity: `.clk` has two meanings.** Snooze/reminders in the expanded parent's `.tago`,
   queued on sub-rows (§5 documents both). Acceptable in-context, but the queued sub-row would
   be unreadable without the word “Queued” — the word, not the icon, is doing the work.

## Every judgement call

- **State → surface mapping.** Queued/single/unread render on the thread list (their risk is
  rollup wording and markers); zero-fail/all-failed/cancelled/native render as open bottom
  sheets (their risk is failure attribution, counters, and composer honesty). Each state sits
  where a reviewer would go to break it.
- **Single-agent case renders on the list, not a sheet.** The state's spec risk is plural
  rollup wording, and the list carries both rollup surfaces (chip + turn row) at once; the
  sheet head repeats the same “Latest turn · 1 agent” string the turn row already proves. The
  named agent appears in the zero-fail/cancelled phones regardless.
- **The single agent succeeded.** A failed single agent would duplicate all-failed's job;
  success lets 3.3 (singular) and 3.4 (no failure styling) be checked at different
  cardinalities (1 vs 10).
- **Zero-fail = all ten succeeded**, not a smaller set: the direct side-by-side against v1's
  ✓ 6 × 4 is the strongest possible demonstration that the failure styling is _absent_, not
  merely quiet.
- **All-failed reasons are identical** (“tool-use budget exceeded” on each of the three rows).
  “Its own reason” means per-row attribution, not distinct causes, and that phrase is the
  scenario's only established failure reason — inventing new causes (e.g. reusing the “SDK
  license” line from v1's APK _result_ text as a _failure_ cause) would rewrite v1's data.
- **Cancelled: the 4 in-flight agents are rendered cancelled, not failed.** v1's narrative has
  those four retrying after budget failures; at cancellation their in-flight retries end as
  cancelled — “cancelled — retry interrupted”. Their earlier failure is not re-shown (that
  would put red in a cancelled screen and blur the state).
- **Cancelled counters use an inline SVG minus-in-circle**, not a “⊖” text glyph — system font
  coverage for ⊖ over `file://` is not guaranteed.
- **Unread = blue dot + the word “unread”**, never a `.tbadge` number (see gap 4). The read
  sibling row is rendered in the same phone so “distinct from read” is checkable at a glance
  without a second page.
- **Native state reuses v1's a4 sheet verbatim** (failed Explore agent) rather than a running
  native — it is the only agent-sheet rendering v1 validated, and its failure simultaneously
  demonstrates per-agent failure attribution.
- **Backdrop lists are adjusted to each phone's state** (zero-fail backdrop says ✓ 10;
  cancelled backdrop says ✓ 6 / ⊖ 4 with the amber counter; all-failed backdrop shows the
  failed task row with its terse reason). A backdrop showing v1's ✓ 6 × 4 while the sheet
  claims ✓ 10 would make the phone contradict itself.
- **New durations for new cardinalities** (single 11s, cancelled 26s, zero-fail 38s) — ticks of
  existing tasks, not invented entities. All repos, threads, tasks, agents, providers, models,
  and usage numbers are v1's.
- **Enabled composers on the done (zero-fail) and failed (all-failed) task sheets** — v1's
  model (“tasks steer; agents don't”), kept consistent; the disabled-with-reason pattern is
  exercised only where a reason exists (cancelled task, native agent).
- **No interactive sheet dismissal or toasts.** Static open sheets; the page's only JS is
  theme, deep-link, and link preservation. Interaction is the flow pages' job.
- **Fixed one typo found on re-read** (`class="font-size: 11.5px"` → `style=`) in phone 7's
  status bar before delivery.
