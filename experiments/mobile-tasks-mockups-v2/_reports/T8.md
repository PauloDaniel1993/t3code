### 4.2 — "What changed from v1 and why"

A dedicated `## What changed from v1 and why` section cites the three findings:

1. **v1 never saw the tasks/agents reference** — v1's `HANDOFF.md` traced the chrome from the
   real `reference-mobile.png` but took the tasks/agents language from a written _description_
   ("the desktop/web sidebar's tasks/agents UI (not embeddable)"). The README states plainly
   that everything derived from it is an interpretation, not a match — **and that this is still
   true in v2**.
2. **v1 hardcoded one scenario** — "10 agents, 6 done, 4 failed" across all four variants; the
   state matrix is the answer, with each of the seven states named.
3. **Contrast failed, measurably** — reported with the **measured** values from `CONTRAST.md`:

   `--dim: #6b7280`. The section notes plainly that the proposal/design's claimed 4.15:1 and
   3.98:1 **do not reproduce**, that the finding stands either way (both value sets fail
   4.5:1), and that the fix was therefore correct. The replacement tokens are quoted with their
   measured ratios (dark `#787e8a`: 4.8552 / 4.6583; light `#6b6b73`: 4.9335 / 5.2820 — all
   PASS).

### 4.7 — measured contrast ratios verified; README points at CONTRAST.md

`CONTRAST.md` was verified against the final `mockup.css` by **independent recomputation**
(WCAG 2.x relative luminance, scripted, from the literal CSS token values — not by trusting
the file):

- **Token tables: every ratio reproduces to four decimal places.** All 40 v2 rows (10 text
  tokens × `--bg`/`--card` × both themes), both v1 baseline rows (4.0952:1 and 3.9291:1 —
  matching the file, and incidentally confirming that the proposal's 4.15/3.98 do not
  reproduce), and every chrome-fix row (FAB all five rows including the old 1.04:1
  invisibility, ALPHA pill both themes, search placeholder both themes, header buttons both
  themes, and the old-formula avatar rows) matched exactly or within ±0.007 (composite rounding
  order). All PASS/FAIL verdicts reproduce.
- **Avatar formula checks reproduce the conclusions:** the new `hsl(h 65% 38%)` worst case
  inside the allowed band is hue 200 (~5.04:1), hue 60 fails (~2.78:1) and is excluded by the
  200–260 rule; the two in-use hues 215 and 255 pass comfortably. My recomputed values differ
  from the table's by ≤0.03 (HSL→RGB integer rounding); every verdict is identical.
- **Effective-contrast section: verdicts reproduce; two rows have small modeling deviations**
  (details under "Could not fully verify" below). The after-fix rows reproduce (4.69:1 /
  4.91:1 sheet, 4.66:1 / 5.28:1 card; send-glyph 3.20:1 / 3.38:1), and the dark sheet composite
  `rgb(15,15,18)` derivation (`--card` at 94% over the black screen) reproduces exactly.
- **Completeness against the final CSS:** the token inventory in `mockup.css` was diffed
  against the tables — every text-capable token (`--fg --muted --dim --info --success --warn
--danger --teal --violet --coral`) is present in both themes; `--primary` is correctly
  excluded as a control background; the disabled-composer `opacity: 0.65` is confirmed absent
  from the final stylesheet (only non-text opacities remain: gesture bar, sheet grabber, toast,
  keyframes).

The README's `## Contrast — measured, not asserted` section points at `CONTRAST.md`, quotes the
headline numbers, and states the standing constraint for the React Native implementation
(token tables cannot see effective contrast — the opacity-multiplier and `hsl()` hue-parameter
defect classes, with their measured values). The claim is checkable: the method is printed at
the top of `CONTRAST.md`, and this pass re-ran it.

## Judgement calls

1. **The stale `index.html` pill was reported, not fixed.** The hard rules say documentation
   only and no HTML changes, and "write it up in your report" for defects. The pill is a
   documentation-flavored placeholder and T7 flipped the same kind of pill when its targets
   landed — a defensible case for editing — but the explicit rule wins over the inference; the
   exact replacement above makes the fix a one-edit decision for the coordinator.
2. **CONTRAST.md's values (4.0952:1 / 3.9291:1) were used for the v1 baseline, not the brief's
   (4.0953:1 / 3.9296:1).** The brief stated the latter but also required every number to come
   from `CONTRAST.md` or the reports, and my own independent recomputation matches
   `CONTRAST.md` to four decimals. The difference is last-digit rounding with no consequence —
   both sets fail 4.5:1 — and the README reports the discrepancy against the _proposal's_
   4.15/3.98 as instructed.
3. **NOTES fixes preserve history rather than rewriting to the final state.** Each correction
   says what was true at build time and what reconciliation changed, with T7 item references —
   the instruction was to keep the authors' reasoning, and an erased mistake is a lost lesson.
   The one partial exception is flow-3's deep-link list, where describing the pre-T7 param set
   first would have documented a contract that no longer exists; there the current contract is
   stated and the four-task extension is credited in the opening paragraph.
4. **flow-1's "Link contract" bullet was converted to "resolved," not deleted.** It sits in the
   Data gaps section but is no longer a gap; keeping it records why `task|apk|local|login` is
   the shared id vocabulary across three pages.
5. **README section order.** v1's skeleton was kept, with three inserted sections — "What
   changed from v1 and why" (after the scenario, since it motivates everything below),
   "Contrast" (after the per-screen notes, before the gaps), and "What v2 does not settle"
   (before the gaps, so the undone alignment pass is read before the unresolved contract
   questions). v1's "Recommendations" section has no v2 analogue (v2 _is_ the recommendation);
   its role is filled by the flow walkthrough in Viewing and the HANDOFF's "The flow is the
   recommendation."
6. **No light-theme caveat invented.** The documents say the light theme is "our translation"
   (the reference is dark-only) — a fact already stated by v2's `index.html` — and make no
   stronger claim.
7. **Verification depth.** Every document, report, and NOTES file was read in full; every
   code-level claim the new documentation makes was checked against the actual files (params,
   redirects, composers, promoted classes, token values, contrast numbers). The four screen
   HTML files were _not_ re-read end to end (state-matrix alone is 1,790 lines); claims about
   their rendered content rely on the authors' reports, T7's reconciliation, and targeted greps
   — which agreed everywhere. No browser rendering was performed, per instructions.
