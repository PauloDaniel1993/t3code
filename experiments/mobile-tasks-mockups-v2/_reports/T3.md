## Page-local CSS rules (and why the shared sheet didn't cover them)

All in the page's `<style>` block; nothing shared was edited or restyled.

1. `.sub.picked { animation: peek-pulse … }` + `@keyframes peek-pulse` — **sanctioned verbatim by CONVENTIONS §3**: `.picked` is in the shared sheet, the pulse is explicitly page-local there and in v1.

3. `.tago .when-open { display: inline-flex; … }`, `.tago .when-closed { display: none }`, `.tgroup.closed .when-open { display: none }`, `.tgroup.closed .when-closed { display: inline }` — the expanded↔collapsed accessory swap on the Wayfinder parent (clock + Settle ↔ "3h"). No shared mechanism exists for state-dependent row furniture.
4. `.sub .olink { color: var(--dim); display: flex; flex: none; align-items: center }` + `.sub .olink:hover { color: var(--fg) }` — the "Open thread" trailing link on task sub-rows. The shared sheet styles `.open` only scoped to `.evt` rows; sub-rows have no trailing-link pattern.

No hardcoded colors anywhere except the sanctioned accent tint `rgba(96, 165, 250, …)` in the
pulse (CONVENTIONS §2's named exception) and the canonical chrome block's own traced values
(`#34d399` battery fill etc.), copied byte-identically as required.

## Judgement calls (made autonomously, no one to ask)

1. **Followed the brief's `?task=<id>` over §3's `?sheet=`/`?view=`** for onward links, and flagged it (above) rather than silently picking one.
2. **"Open thread" got a visible affordance**: a 12 px trailing ↗ on each task sub-row. The v2 index says flow-2's sheet also has "Open thread" — mine is the direct path from the list, which is what makes this screen the flow's entry. Cost: ~20 px per task row. Alternative considered and rejected: no affordance here (leaves the brief's third link unrealized on my screen).
3. **Turn row navigates** to `flow-2-peek?task=task` instead of v1's "view only" toast — the sheet's agent block is where its agents are view-only, so the navigation doesn't contradict the view-only semantics; it operationalizes them.
4. **Failure reason as tooltips + devicecap, not an inline line.** The turn row is single-line; adding "budget exceeded" inline would truncate "Latest turn · 10 agents" to meaninglessness at 320 px, and §5's own example renders `× 4` bare on this exact screen. Per-agent reasons in words remain one tap away in the peek sheet, which is the design split: list = counts, sheet = reasons. Because all four failures share one reason, the tooltip loses nothing.
5. **Plain thread rows toast instead of navigating.** flow-3-task models the mockups task and its parent — not the other five real threads. A toast that says so honestly beats a link into an unmodeled page. The expanded Wayfinder parent could arguably link to `flow-3-task?view=parent` (it IS that parent); I left it toasting for uniformity with the redirect group, which has no modeled destination. If the coordinator wants it linked, it's a one-line change.
6. **`?groups=` defaults to expanded** (v1's rendering), `collapsed` is the only recognized non-default value; unknown values fall back to expanded per §3's "never render blank".
7. **dchip is the collapse toggle** (chevron flips, tooltip updates). It was the only honest target — the chip already reads like a disclosure control. `stopPropagation` keeps chip taps from also firing the row toast.
8. **Added `title="Claude Code"` / `title="Codex"` to every `.tprov`** — v1 titled only some rows; chrome.html titles all of them. Consistency with the canonical chrome.
9. **No `cursor: pointer` on chips/links.** The shared sheet deliberately uses default cursors (`.trow`, `.seg a`); I matched it rather than "fixing" it page-locally.
10. **Kept `data-unit` ids as the task ids in links** (`task`, `apk`, `local`, `login`) so my `?peek=`, flow-2's `?task=`, and flow-3's `?task=` all speak one vocabulary.
