## Page-local CSS rules and why (shared-sheet gaps — coordinator decision needed)

All in the page's own `<style>` block; `mockup.css` untouched.

1. `.tail { display: contents }` — wrapper so a lifecycle state's timeline rows keep the `.tl`
   flex gap while toggling as one block. No shared equivalent (`.tl` children are flat).
2. `.hidden { display: none }` — display utility for state toggling. v1 option 4 carried the
   same page-local utility; the shared sheet has none. **Declared after `.tail` so the toggle
   wins the cascade** (equal-specificity source-order bug caught and fixed during self-check).
3. `.composer.disabled { opacity: 0.65 }` and `.composer.disabled .send { background:
var(--border2); color: var(--dim) }` — the sheet composer has `.sh-composer.disabled` +
   greyed `.sh-send`; the standalone `.composer` (the one §4 says detail screens swap in) has
   no disabled equivalent. Values mirror the sheet's exactly. **Recommend promoting to
   `mockup.css`** — flow-2's agent sheet already needed this pattern, and any detail screen
   with an unsteerable composer will need it again.
4. `.evt.failed { color: var(--danger); border-color: rgba(248,113,113,0.35); background:
rgba(248,113,113,0.08) }` — timeline `.evt` only has `.wake` in the shared sheet;
   `.sh-evt.failed` exists but is sheet-scoped (no border/background). Tint values mirror
   `.sh-btn.danger` / `.chip.danger` exactly, i.e. the sheet's own theme-agnostic danger tints —
   the sanctioned §2 exception, no new hardcoded colors.

No class in the inventory failed to fit; the `.wcard` / `.wrow` / `.evt` / `.composer` /
`.tbar` anatomies covered the whole screen.

## CONVENTIONS.md — missing / wrong / ambiguous

- **Gap: flow-3 has no declared lifecycle param.** §3 declares only `?view=parent|task` for
  `flow-3-task/`, but the brief required deep-linkable lifecycle states. I used
  `?state=running|complete|failed` — same param name as state-matrix's `?state=` (consistent
  vocabulary), disjoint per-page value sets. Worth adding to the §3 table.
- **Gap: `?view=parent` has no honest target in v2.** The declared value assumes a parent view
  that v2 doesn't build (brief: "carry forward the TASK half only"). §3 says unknown values
  fall back gracefully, but `parent` is a _known_ value with no owning surface — the contract
  should say whether redirect (my choice) or silent fallback is correct.
- **Gap: no `.composer.disabled` / `.evt.failed` / `.hidden` in the shared sheet** (page-local
  stopgaps listed above). `.composer.disabled` is the one most likely to recur — §4 makes
  `.composer` the detail-screen standard and §7.2 mandates explained-disabled composers.
- **Ambiguity: `.usage` vs `.wsub` for failed rows.** §5 sanctions both ("reason rides in
  `.wsub` (or `.usage` with the reason appended, v1 option 4 style)"). I chose `.wsub`
  ("failed — tool-use budget exceeded", the §5 wcard example verbatim) because it's shorter at
  narrow widths and puts the reason first; it drops the failed runs' usage figures, which only
  v1's Agents tab had room for. Fine as-is, but a reviewer comparing against v1's Agents tab
  should know the figures were deliberately dropped, not lost.
- **Not a defect, worth recording:** v1 option 4's own a7 row ("Bottom-sheet layout pass")
  showed a bare `failed` chip with no reason in its usage line — the one place v1 option 4
  itself broke rule 1. Fixed here.

## Judgement calls (all reversible, all documented in NOTES.md)

1. **Back target = the peek sheet** (`flow-2-peek?sheet=task`), not the list. The user opened
   the thread from the sheet's "Open thread"; Android back returns to the previous screen.
   v1's chevron named the parent thread; v2 has no parent page, so the title is "Back to the
   task sheet" and the parent relationship is carried by the provenance row + "See in list →".
2. **`?view=parent` redirects** to `flow-1-list?peek=task` instead of silently falling back to
   the task view. A redirect preserves the theme and lands where the parent actually is.
3. **Complete state keeps an enabled composer** ("Message this task…") — v1 option 4 explicitly
   showed "T1, the finished one" with "a fully enabled steer composer", and the model says task
   threads are durable and steerable. Disabling it would contradict v1.
4. **Failed state disables the composer with reason + offers Retry.** Steering is defined as
   guidance into an in-flight turn; a stopped task has none. This is the screen's
   explained-unavailable-control demonstration (brief hard rule 2). The alternative (message =
   retry) is defensible too; NOTES.md flags it as a contracts decision.
5. **Failed/complete keep the same turn card (✓ 6 × 4).** The turn record is scenario canon;
   the retry turn is narrated in words only — no invented second agent card, no invented retry
   outcomes, no invented usage figures (rule 4).
6. **Provenance moved to a `.evt` row** (per §5 "provenance … goes here") with the §4-canonical
   subtitle "task · runs in its own thread · Opus 4.7" plus a state word, replacing v1's
   longer subtitle — provenance now appears once, in the timeline, with a working link.
7. **Composer follows the §4 canonical block** (Attach chipbtn with label, send) — v1's
   icon-only attach + hardcoded-`#8f9cf5` model chip were not carried (§2 hardcoded-color ban;
   the model already lives in the header subtitle).
8. **`?state=queued|cancelled` not implemented** — those cardinalities belong to state-matrix
   per §7.6; unknown values fall back to `running`.
