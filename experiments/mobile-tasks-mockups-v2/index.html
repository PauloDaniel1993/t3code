Mobile tasks — the converged flow

v2 converges v1's four options into the flow its own README recommended — thread list → bottom-sheet peek → full task view — and renders the lifecycle states v1 never showed: queued, one agent, zero failures, all failed, cancelled, returned-unread, and the native in-session agent that must visibly refuse steering. The v1 set stays frozen as the comparison baseline. Sibling mockups: ../thread-tasks-mockups/, ../subagent-view-mockups/.

The reference is dark-only; the light theme is our translation.

Flow 1 — Thread list, expanded groups

open →

The entry screen: the app's real thread list with expanded parent rows (clock + ✓ Settle pill, ⌄ 1 task · 10 agents disclosure chip) and guide-line sub-rows nesting thread → tasks → a task's turn. Deep link ?peek=task|turn|apk|local|login highlights a row · ?groups=collapsed renders every group closed.

Flow 2 — Bottom-sheet peek

open →

Tapping a task row slides up the glass bottom sheet: status, chips, prompt, latest activity, the turn's agents, Cancel while running, an enabled steer composer, "Open thread". An agent's sheet keeps the same anatomy but disables the composer with the reason in words and swaps in "Show in transcript". Deep link ?sheet=task|apk|local|login|a4 (a4 is a failed agent); ?task=<id> is the alias flow 1's rows emit.

Flow 3 — Full task view

open →

A task opens as a normal pushed thread view — own transcript, steer composer, parent as back target — because "Open thread" must land somewhere. All four tasks are modelled: ?task=task|apk|local|login picks one · ?state=running|complete|failed switches the mockups task's lifecycle · ?view=parent redirects to the list.

State matrix — every lifecycle state side by side

open →

The deliverable v1 lacked: queued, exactly one agent, zero failures, all agents failed (each with its reason), cancelled mid-flight, returned-but-unread, and the native in-session agent refusing a steer — one screen per state, side by side. Deep link ?state=… jumps to a state (ids in CONVENTIONS.md).
